## Стратегии

| Стратегия | Контекст | Обслуживание |
|---|---|---|
| Sliding Window | Последние 6 сообщений | Без дополнительных LLM-вызовов |
| Sticky Facts | Facts в виде ключ–значение + последние 6 сообщений | Обновление перед каждым новым пользовательским сообщением |
| Summary | Отдельная сводка старого префикса + несжатый хвост | Обновление при 10 несжатых сообщениях, минимум 6 остаются целиком |

Полный архив, включая tool_calls и результаты, сохраняется во всех режимах. Границы окна и summary проходят между завершёнными пользовательскими ходами, поэтому хвост может быть длиннее 6. Это сохраняет протокол нескольких последовательных инструментов. При новом вопросе в коротком окне остаётся минимум 6 сообщений вместе с новым сообщением, округляя границу к началу хода.

При переходе на summary накопленный старый архив сжимается перед первым основным ответом, если достигнут порог: его не нужно сначала отправлять целиком. Просмотр режима не запускает сжатие и показывает пока сохранённое состояние. Переключатель действует на следующий запрос; выбранный режим сохраняется в браузере. В инспекторе показана выбранная история с system; схемы инструментов передаются отдельно. Режим `full` оставлен в API для регрессионных проверок, в интерфейсе доступны три стратегии задания.

Facts обновляются отдельным запросом с предыдущим блоком фактов и новыми сообщениями до текущего пользователя включительно. В них попадают результаты прошлого инструментального хода. Вопросы не должны становиться новыми фактами; исправления заменяют прежнее значение. На проводе применяется строгая JSON Schema со списком `{key, value}`, затем валидированные пары преобразуются в словарь. Ограничены число ключей, размер, типы и дубликаты. Старый формат объекта ключ–значение также проходит локальную валидацию для совместимости тестовых моделей. Генерация facts не использует инструменты, лимит — 768 токенов.

Если переключиться на facts после другой стратегии, агент последовательно обработает пропущенные пользовательские сообщения, а их расходы попадут в метрики. Инспектор до отправки показывает сохранённые facts; он не вызывает платную экстракцию, поэтому оценка следующего запроса предварительная.

Ошибка facts останавливает ход до ответа пользователю, старые архив и факты остаются прежними. Если экстракция прошла, а основной ответ не получен, новые факты также не фиксируются отдельно от хода. Ошибка summary после готового ответа сохраняет ответ с предупреждением и прежнюю сводку. Все попытки и расходы, включая неизвестный usage, сохраняются. Автоматических повторов и fallback нет.

## Checkpoint и ветки

1. Начните разговор и дождитесь завершения хода.
2. Нажмите «Сохранить checkpoint».
3. Укажите имя первой ветки и нажмите «Создать ветку».
4. Выберите тот же checkpoint, задайте имя второй ветки и создайте её.
5. Переключайтесь между ветками кнопками слева и обсуждайте разные решения.

Checkpoint — неизменяемый снимок архива, summary, facts, профиля и ревизии. Обе ветки получают независимые копии. Ветка, созданная позже, всё равно начинается с сохранённого checkpoint, а не с текущего состояния родителя. Незавершённый ход нельзя превратить в checkpoint. Создание и переключение веток не вызывает LLM.

SQLite schema v4: добавлены `facts_states`, `checkpoints`, `branches`; миграции v1–v3 сохраняют прежние сообщения и summary. Запись успешного хода и обоих видов памяти атомарна. При сбое создания ветки все её строки откатываются. Новые вызовы и их стоимость принадлежат только ветке; старые вызовы родителя не копируются. Импортированные ходы помечены `imported` и не создают новых списаний. При перезапуске восстанавливаются все разговоры, точки ветвления и память. Хеши связывают память с исходным префиксом архива.

```bash

Проверяются окно, tool-протокол, обновления и исправления facts, все три стратегии на одном сценарии, независимость веток, перезапуск, миграции, сетевые ошибки, блокировка бюджета и откат SQLite. Полный эксперимент проверяется через HTTP-мок. Подробности — `BDD.md`.

## Реальный эксперимент

```bash
python -m agent10.experiment --budget-rub 20
```

Источник по умолчанию — точный архив `../D4/submission/experiment.json`. Команда проверяет 28 сообщений, исходные 12 запросов и заранее заданные десять эталонов; сохраняет SHA-256 файла. Ответы исходного разговора не генерируются заново: это обеспечивает одинаковую историю для трёх стратегий. Можно указать другой совместимый файл через `--source`.

На этом архиве заново строятся summary и facts. Затем каждый из десяти вопросов задаётся каждой стратегии отдельно от одной и той же исходной истории. Порядок стратегий циклически меняется. Предыдущие контрольные ответы не подсказывают следующие; эталоны не попадают в запросы. Facts обновляются и на вопросах проверки — эти дополнительные вызовы включены в цену.

Проверки сумм разрешают инструменты, поэтому отчёт отдельно считает верные ответы **без** инструментов и верные с повторным получением данных. Наличие правильного ответа после find_order ещё не означает сохранение факта в памяти.

В том же прогоне создаются checkpoint и две ветки: 150000 ₽ / 2026-12-20 и 320000 ₽ / 2026-12-25. Агент должен независимо вспомнить обе пары; родитель остаётся с исходными договорённостями. После закрытия SQLite приложение открывается заново и проверяет восстановление веток.

Команда создаёт каталог `results/ГГГГ-ММ-ДД_ЧЧ-ММ-СС_идентификатор`: `report.md`, `summary.csv`, `details.csv`, `experiment.json`, `trace.json`, рабочую SQLite. Каждый запуск — новый платный прогон с отдельным бюджетом; остановленные прогоны не повторяются и не возобновляются автоматически. При нескольких ручных запусках нужно вычесть уже учтённые расходы из общего лимита.

В таблице учтены все расходы обслуживания памяти. Поддержка веток измерена отдельно. Размер кода — непустые строки AST узлов реализации конкретной стратегии, без общих Agent, Store, API, интерфейса и тестов; это ограниченная, но воспроизводимая оценка сложности.

Фактические токены и стоимость берутся из usage API. Локальная оценка JSON отличается от серверного chat template. При неизвестном списании бюджет удерживает резерв; это оценка, а не гарантия банковского лимита. Результаты одного сценария не являются статистической гарантией качества.

Итоговые проверенные данные находятся в `submission/`. Личные базы, новые результаты, `.env`, `.venv`, токенизатор и `.log` исключены из Git. Журналы UTF-8 имеют дату до секунд и уникальный суффикс, ключ маскируется. Сценарий видео — `VIDEO.md`; само видео необходимо записать отдельно.
