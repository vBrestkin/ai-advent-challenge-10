# День 9: сжатие истории

Python + FastAPI, локальный веб-чат на http://127.0.0.1:8063. Модель Qwen3 14B через Polza.ai, маршрут deepinfra/fp8; параметры и тарифы проверяются по каталогу перед реальными запросами. Предыдущие дни не изменены.

## Запуск

```bash
cd /Users/brestkin/ai-advent-challenge-10/W2/D4
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[test]'
```

Ключ `POLZA_API_KEY` наследуется из `.env` прошлых дней (в том числе W1/D1), затем из текущей `.env`; переменные окружения имеют приоритет. В браузер ключ не передаётся. Токенизатор можно скопировать из `../D3/data/tokenizer.json`; контрольная сумма проверяется при загрузке.

## Как устроена память

- `Agent` хранит полный протокол. Отдельный `context_builder` выбирает контекст каждого LLM-вызова, включая продолжения после инструментов.
- Режим **Полная история** отправляет архив целиком. **Сжатие истории** отправляет summary и несжатый хвост. Переключатель влияет на следующий запрос, а архив не меняется.
- После успешного хода при накоплении **10 несжатых сообщений** сворачивается старый префикс, остаётся **минимум 6 последних** сообщений. Под сообщениями считаются все роли, включая tool. Если граница разрывает ход, сохраняется больше 6 сообщений, а сжатие может быть отложено.
- При обновлении модель получает предыдущую сводку и только новый старый префикс. Инструменты для этой генерации отключены, лимит ответа — 512 токенов. Неудачное сжатие не повторяется автоматически: ответ пользователю сохраняется с предупреждением, старая память остаётся пригодной. Следующий успешный пользовательский ход может снова попытаться обновить сводку.
- SQLite schema v3: полный архив в `sessions`, summary отдельно в `memories`, а обращения и расходы — в `calls`. Сводка, граница `covered` и SHA-256 покрытого префикса фиксируются атомарно вместе с успешным ходом. Миграции v1/v2 сохраняют данные. Повреждение останавливает работу, исходная база не заменяется.
- После перезапуска восстанавливаются и архив, и summary. Контекст инструментов не разрывается. Остались ограничения предыдущего дня: максимум 6 LLM-раундов на запрос, без сетевых повторов и fallback.
- Сводка — модельный пересказ: факты могут потеряться или исказиться. Полный архив позволяет проверить исходные данные. Вопросы «что помнишь» следует оценивать по конкретным деталям.

## Реальный эксперимент

```bash
python -m agent9.experiment --budget-rub 20
```

Каждый запуск создаёт **новый платный прогон** с отдельным бюджетом в `results/ГГГГ-ММ-ДД_ЧЧ-ММ-СС_идентификатор`. Возобновления и скрытых повторов нет. Учёт включает общую подготовку разговора, все сводки, проверки и инструментальные продолжения. Неизвестное списание удерживает резерв бюджета. Резерв — консервативная локальная оценка, а не гарантия банковского лимита.

Сценарий и десять ожидаемых деталей заданы в `experiment.py` **до** запросов. Создаётся один диалог из 12 пользовательских ходов, ожидается 28 сообщений всех ролей (без system), включая два последовательных инструмента. Из точных снимков этой истории последовательно строится сжатая копия. У двух режимов одинаковые исходные данные и ответы собеседника. Перезапуск lifespan приложения проверяет восстановление памяти из SQLite. Это не отдельный OS-процесс; межпроцессный сценарий сохранения проверялся в предыдущий день.

Каждый из десяти вопросов задаётся отдельно от одной и той же конечной истории в обоих режимах, чередуя full/summary. Ответы предыдущих проверок не подсказывают последующие. Эталоны не передаются ни в summary, ни в проверочные запросы. Проверки сумм допускают инструменты; повторное обращение к инструменту явно видно в `steps` и trace. Таблица показывает такие случаи отдельно в выводах.

Оценка: JSON с единственным полем `value`, точное совпадение с заранее заданными вариантами после нормализации регистра/пробелов. Форматная ошибка и смысловая ошибка различаются при ручном разборе `details.csv`. Это один сценарий, а не статистический бенчмарк.

Результаты: `report.md`, `summary.csv`, `details.csv`, `experiment.json`, `trace.json`. В JSON включены снимки сводок, полный архив, серверный usage и ответы. Расход на сводки входит в итоговую цену summary; подготовка диалога показана отдельно как общая для режимов. Локальная оценка контекста до/после использует закреплённый токенизатор Qwen и JSON, но отличается от серверного chat template.

В `submission/` хранится проверенный итоговый отчёт и обезличенные учебные данные для Git. Логи с датой до секунд, `.env`, личная история SQLite, результаты новых прогонов и JSON-токенизатор исключены из Git.
