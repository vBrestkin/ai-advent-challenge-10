# День 6 · Первый агент · W2/D1

Локальный веб-чат с агентом, который самостоятельно выбирает инструменты через
Polza.ai. Реализованы find_order и calculate. Агент хранит полный протокол
успешных ходов в памяти процесса, включая tool_calls и сообщения tool.
Сохранение между перезапусками запланировано на W2/D2.

## Запуск

Окружение в репозитории подготовлено.

```bash
cd /Users/brestkin/ai-advent-challenge-10/W2/D1
.venv/bin/agent6
```

Откройте http://127.0.0.1:8060. Если сервер уже работает, используйте открытый
адрес. Остановка — Ctrl+C в терминале сервера.

Для установки с нуля:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[test]'
```

Ключ читается из W1/D1 → D2 → D3 → D4 → D5 → локальный .env W2/D1 → окружение.
Более позднее значение перекрывает раннее, включая пустое. Имя переменной
POLZA_API_KEY. Ключ остаётся на сервере. По умолчанию используется
`google/gemini-2.5-flash-lite`, маршрут `google-ai-studio/flex`, без fallback.

## Проверка

```bash
.venv/bin/python -m pytest -v
```

46 офлайн-тестов. Реальный платный пилот через HTTP-интерфейс приложения:

```bash
.venv/bin/python -m agent6.pilot
```

Команда создаёт новые API-запросы и обновляет учебные материалы submission/.
Пилот выполнен успешно, шесть API-вызовов, известная стоимость 0.03274418 ₽.
Сценарии — без инструментов, калькулятор, поиск заказа с последующим калькулятором.
В trace.json подтверждены отдельные последовательные обращения к модели.

В браузере кнопка «Новый разговор» создаёт независимый контекст. Выбор разговора
восстанавливает его сообщения из памяти сервера. Справа показаны шаги последнего
успешного хода. Во время запроса отображается статус ожидания. Панель шагов
появляется после завершения хода. На узком экране она расположена под чатом.

## Устройство

- agent.py инкапсулирует цикл и историю. Интерфейс вызывает Agent.run().
- transport.py отправляет tools и tool_choice=auto, принимает tool_calls даже
  при content=null. Сохраняет возвращённое assistant-сообщение с метаданными.
- tools.py содержит две функции, JSON Schema и проверку аргументов.
- web.py предоставляет веб-страницу, список разговоров и API чата.
- index.html отображает текст через textContent, включая ответы модели.

Лимит — шесть обращений к LLM на ход и до четырёх вызовов инструментов на ответ.
При ошибке незавершённый ход сохраняется в журнале, успешная история остаётся
на предыдущем состоянии. Автоматические повторы отключены. Неизвестные имена
и неверные аргументы возвращаются модели как ошибка инструмента. Калькулятор
принимает строки, четыре операции, конечные числа до 1e12 по модулю и показатель
Decimal от -12 до 12. Деление использует стандартную точность Decimal 28 знаков.
Операции с заказами читают учебный словарь, суммы записаны в RUB.

Сервер обслуживает один ход одновременно, конкурентная отправка получает 409.
Пустые запросы отклоняются, неизвестная сессия получает 404. Подключение ограничено
10 секундами, ожидание данных 180 секундами. Общий лимит генерации 4096 токенов,
reasoning запрошен с бюджетом 1024. Длинные беседы ограничены контекстом провайдера.

Каждый запуск сервера или пилота создаёт logs/YYYY-MM-DD_HH-MM-SS_id.log с правами
600. В журнале HTTP-запросы, ввод, запросы к модели, ответы, инструменты, метрики,
ошибки и остановка. Ключ маскируется, Authorization не записывается. При физическом
отказе диска выполнение останавливается, уже полученный ответ может не сохраниться.
Журналы содержат тексты разговоров. .env, .venv и *.log исключены общим .gitignore.

При ошибке соединения исход платного вызова может остаться неизвестным.
Повторная отправка пользователем создаёт новый запрос.
