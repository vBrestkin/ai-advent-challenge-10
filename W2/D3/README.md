# День 8 · Токены и стоимость · W2/D3

Самостоятельная версия веб-агента с полным контекстом в SQLite, локальными
оценками и фактическим usage API. Используется qwen/qwen3-14b на закреплённом
маршруте deepinfra/fp8. Каталог маршрута заявляет контекст 40960 токенов.
Выбрана одна модель для всех трёх сценариев, а также проверки инструментов.

## Запуск

```bash
cd /Users/brestkin/ai-advent-challenge-10/W2/D3
.venv/bin/agent8
```

Откройте http://127.0.0.1:8062. Текущая рабочая копия и токенизатор подготовлены.
Остановка сервера — Ctrl+C. Для одной базы допускается один процесс сервера.
Порт D8 — 8062, D7 — 8061, D6 — 8060.

Установка в новой копии:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m agent8.setup_tokenizer
.venv/bin/agent8
```

JSON-токенизатор взят из официального репозитория Qwen на ModelScope. Контрольная
сумма SHA-256 закреплена в metrics.py и проверяется при загрузке и установке.
Веса модели и код репозитория не загружаются. Файл находится в data/tokenizer.json,
он исключён из Git. Без этого файла веб-чат показывает приближение UTF-8 bytes/4
с явной меткой estimate. Реальный эксперимент требует локальный токенизатор Qwen.
Если контрольная сумма существующего файла отличается, запуск прекращается.

Ключ POLZA_API_KEY читается из .env W1/D1 → D2 → D3 → D4 → D5 → W2/D1 → W2/D2
→ W2/D3 → окружение. Поздние значения перекрывают ранние, включая пустые.
На запуске проверяются каталог, выбранный маршрут, tools, параметры, окно
контекста, лимит генерации и рублёвые тарифы. Если проверка не пройдена,
сервер завершает запуск. Ключ в браузер не передаётся.

## Что показывают метрики

Перед отправкой ввод обрабатывается локально, обращения к LLM нет:

- «Новый текст» — число токенов текста по закреплённому токенизатору.
- «История» — оценка токенов JSON сохранённых сообщений, включая tool_calls/tool.
- «Запрос со схемами» — оценка system + messages + описаний инструментов.
- Резерв ответа — max_tokens=4096. Показан заявленный размер окна маршрута.

Серверное оформление ролей и инструментов отличается от нашего JSON. Поэтому
даже с токенизатором Qwen полный запрос до отправки остаётся оценкой. В реальном
коротком запросе оценка составила 265, а usage.prompt_tokens — 844. Эти числа
сохранены отдельно. Предварительная оценка не гарантирует вместимость запроса.

После ответа показаны фактические prompt/completion/total/reasoning из usage API.
Reasoning входит в completion/total и не прибавляется повторно. Стоимость
берётся из usage.cost_rub. В одном пользовательском ходе может быть несколько
HTTP-вызовов LLM, все они суммируются. У хода и всего разговора есть метрики.
Фактические значения в панели подписаны как известные, рядом показаны счётчики
неизвестных списаний и total. Неизвестное значение не заменяется нулём.

Метрики сохраняются в SQLite вместе с session_id/attempt_id и восстанавливаются
после перезапуска. Таблица calls содержит запись до отправки и уточнённый
результат после ответа. После аварии pending-записи становятся uncertain.
Такие попытки консервативно учитываются как возможно отправленные.
При ошибках запросов сохраняются HTTP-статус, исходный ответ и резерв цены.

## Реальный эксперимент

```bash
.venv/bin/python -m agent8.experiment --budget-rub 20
```

Команда делает платные API-запросы. Сначала проверяет инструменты поиском заказа
и расчётом скидки. Затем выполняет короткий запрос, восемь ходов одного растущего
разговора и продолжение с превышением контекста. В каждом длинном ходе один и тот
же объём нового текста, ответы короткие. short и pilot_tools используют отдельные
сессии. Полная история передаётся без сжатия и усечения.

Для overflow лабораторный runner явно разрешает обход локальной проверки
вместимости. Текст содержит 50018 локальных токенов, весь запрос оценён в 64334.
Polza.ai вернул HTTP 400 с reason=inputExceedsContext. Это проверка настоящего
HTTP-отказа шлюза. Выполнение запроса самой моделью не подтверждено.
Оценка ~86744 в тексте ошибки принадлежит шлюзу и не считается фактическим usage.
Отдельный local_guard затем проверяет тот же ввод с локальной защитой, без POST
к LLM. В обычном веб-чате обход локальной проверки не включается.

Бюджет включает пилот, успешные ответы и резервы неизвестных списаний. Перед
каждым запросом резервируется стоимость входа по UTF-8 байтам с запасом 2048 и
максимального выхода по тарифам +1%. Маршрут фиксирован, fallback и автоматические
повторы отключены. Это локальная защита, а не гарантия банковского биллинга.

Каждый запуск создаёт новую папку results/<дата_id> и новые запросы. Автоматического
resume эксперимента нет. При ошибке длинного разговора runner останавливается
и оставляет частичный отчёт. Для нового прогона бюджет задаётся заново, расходы
отдельных запусков учитывайте совместно. Обычные сообщения в веб-чате тарифицируются
отдельно от лимита экспериментального runner.

Выполненный прогон — results/2026-11-15_13-28-28_6268ede7e3ea. Его отчёт и
проверенные данные скопированы в submission/. Известная цена 1.04134164 ₽,
одно неизвестное списание после HTTP 400. Резерв 5.7407720321 ₽, учтено
6.7821136721 ₽ из 20 ₽. Резерв не равен фактическому расходу.

## Хранение и совместимость

По умолчанию data/history.sqlite3. Путь можно изменить через --data-dir или
AGENT8_DATA_DIR. Браузер запоминает выбранный session_id, контекст и метрики
хранятся на сервере. База схемы v1 мигрирует транзакционно в v2 с таблицей calls,
прежние сообщения, tool IDs и метаданные сохраняются. Исторический usage v1
в calls не восстанавливается, поскольку прежняя версия хранила его в журналах.

Каждый день использует свою папку данных. При ручном переносе базы D7 диалоги
прежней модели можно просмотреть, а для общения с Qwen создайте новый разговор.
Профиль с моделью, параметрами и системной инструкцией проверяется перед отправкой.
Полный успешный протокол и отображаемый ход сохраняются атомарно. Неуспешный
ход остаётся в attempts и calls, успешная история сохраняется. Следующее
сообщение использует последний успешно сохранённый контекст.

Два инструмента, независимость разговоров и восстановление после перезапуска
сохранены. Аргументы проверяются JSON Schema. На ход до шести обращений к LLM,
на ответ до четырёх инструментов. Максимальная длина нового сообщения 500000
символов, локальный лимит контекста проверяется отдельно. Сеть: 10 секунд
подключение, 180 секунд ожидание данных. Повреждённая база не заменяется пустой.

## Тесты, логи и материалы

```bash
.venv/bin/python -m pytest -v
```

98 офлайн-тестов. Новые поведенческие проверки написаны до реализации, включая
полный эксперимент через HTTP с MockTransport. BDD.md фиксирует красные и
зелёные этапы. Видео ещё нужно записать, VIDEO.md содержит реальные команды,
план демонстрации и короткую речь по полученным результатам.

Каждый запуск пишет UTF-8 logs/YYYY-MM-DD_HH-MM-SS_id.log с запросами, ответами,
инструментами, метриками, ошибками, CLI-выводом и восстановлением. Ключ маскируется,
Authorization не сохраняется. Логи содержат текст разговора. Базы, рабочие
results/, .env, окружение и .log исключены из Git. Подготовленные данные submission/
включают только синтетический учебный сценарий и предназначены для репозитория.
