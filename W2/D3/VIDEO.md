# Видео дня 8 · Токены и стоимость

План на 5–7 минут. Команды experiment и сообщения в чате делают платные запросы.
При повторной съёмке используйте результаты своего нового прогона. .env и личные
журналы не показывайте. Токенизатор уже установлен в текущей рабочей копии.

1. Покажите BDD.md и выполните офлайн-тесты:

```bash
cd /Users/brestkin/ai-advent-challenge-10/W2/D3
.venv/bin/python -m pytest -v
```

«Сначала написаны проверки метрик. Отдельно проверяются неизвестные значения,
несколько обращений к LLM за ход, сохранение после перезапуска и переполнение».

2. Запустите веб-чат, если он ещё не работает:

```bash
.venv/bin/agent8
```

Откройте http://127.0.0.1:8062. Создайте новый разговор. Введите:
«Найди сумму заказа A-104 и рассчитай цену со скидкой 15%».
До отправки покажите локальное количество токенов нового текста и оценку
полного запроса со схемами. Нажмите «Отправить», дождитесь ответа.

«Локальный счётчик использует токенизатор Qwen. Полный запрос до отправки —
оценка, поскольку сервер оформляет роли и инструменты по-своему. Фактические
значения я беру из usage API после ответа».

Покажите два инструмента и три обращения к LLM. Объясните, что вход и выход
суммируются по всему пользовательскому ходу, а reasoning уже входит в total.
Обновите страницу: стоимость и токены разговора восстановятся из SQLite.

3. Выполните настоящий эксперимент:

```bash
.venv/bin/python -m agent8.experiment --budget-rub 20
```

«Для сравнения выбрана Qwen3 14B с окном маршрута 40960 токенов. Сначала
проверяю инструменты, затем короткий запрос и восемь ходов с растущей историей.
После этого отправляю продолжение, превышающее контекст».

Покажите строки short, long и overflow. Ожидание можно ускорить при монтаже.
Команда создаёт изолированную базу и новую папку results/<дата_id>, существующие
разговоры веб-чата остаются в data/history.sqlite3.

4. Откройте report.md в папке, которую вывела команда. Покажите таблицы short/long/
overflow и turns.csv. В выполненном прогоне короткий запрос имел 844 входных
токена, длинный вырос с 2567 до 14831 на ход. Новое сообщение при этом содержало
1737 локальных токенов, ответы были короткими — по 6 токенов.

«В каждом новом запросе оплачивается передаваемая история. Поэтому стоимость
растёт даже при коротких ответах. Важно считать все обращения цикла агента».

5. Покажите исходную ошибку в разделе overflow:

- Шлюз Polza.ai вернул HTTP 400, reason=inputExceedsContext.
- Приложение отобразило ошибку upstream как HTTP 502.
- Успешная история перед ошибкой и после неё совпала.
- local_guard показан отдельно, при нём POST к LLM отсутствует.

«В лабораторном overflow я явно разрешил пропустить локальную проверку, чтобы
увидеть настоящую реакцию API. Запрос отклонил шлюз, выполнение самой LLM
не подтверждено. Оценку токенов в тексте ошибки я не подставляю в usage».

6. Покажите бюджет и неизвестное списание. В подготовленном прогоне известно
1.04134164 ₽, резерв после отказа 5.7407720321 ₽, учтено 6.7821136721 ₽ из 20 ₽.
Резерв не является фактическим расходом. При новом прогоне значения изменятся.

Короткая речь для вывода:

«В коротком запросе было 844 входных токена, в конце длинного диалога — 14831.
Стоимость одного длинного хода выросла примерно с 4 до 21 копейки, хотя ответы
оставались короткими. При переполнении Polza.ai отклонил запрос с HTTP 400,
а сохранённая история осталась целой. Расход успешных запросов известен,
для отказа без usage оставлен резерв. Следующим шагом проверю, сколько токенов
экономит сжатие истории и какие детали при этом теряются».
