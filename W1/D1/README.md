# День 1 — первый запрос к LLM через API

Python CLI отправляет один запрос в Polza.ai и печатает ответ. Каждый запуск,
включая помощь и ошибки настроек, сохраняет текстовый журнал в `logs/`.

## Установка

Python 3.9 или новее. Команды выполняются в терминале:

```bash
cd /Users/brestkin/ai-advent-challenge-10/W1/D1
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[test]'
cp .env.example .env
```

Откройте `.env` в редакторе и заполните `POLZA_API_KEY` своим ключом.
Переменные окружения имеют приоритет над `.env`. Файл загружается из папки D1
независимо от текущей директории терминала. Ключ нельзя добавлять в Git или
показывать на видео. В репозитории он исключён через `.gitignore`.

`LLM_MODEL` — полный ID модели из каталога. В примере указана
[`google/gemini-2.5-flash-lite`](https://polza.ai/models/google/gemini-2.5-flash-lite).
Доступность и текущую цену проверяйте в кабинете; это пример для дня 1,
а не выбор модели для всех последующих экспериментов.

## Запуск

```bash
.venv/bin/day1 "Объясни в двух предложениях, что такое API."
.venv/bin/day1 --help
```

Без установки пакета можно запускать модуль:

```bash
PYTHONPATH=src .venv/bin/python -m day1 "Привет!"
```

Параметры: `--max-tokens` (по умолчанию 4096), `--connect-timeout` (10 секунд),
`--read-timeout` (60 секунд). Таймаут чтения ограничивает ожидание данных,
а не гарантирует общий предел длительности всего процесса.

Программа использует HTTP напрямую через `httpx` и OpenAI-совместимый формат
Polza.ai. Стриминг, перенаправления и повторы HTTP-клиента отключены.
В запросе также отключён fallback шлюза. При таймауте или разрыве соединения
запрос уже мог быть обработан провайдером: программа не отправляет его повторно.

## Журналы

Имя: `logs/YYYY-MM-DD_HH-MM-SS_<уникальный идентификатор>.log`.
Дата и время локальные, в каждой записи есть смещение часового пояса.
Идентификатор предотвращает перезапись при запуске в одну секунду.

В журнал попадают этапы запуска, запрос, модель, параметры, HTTP-статус,
полученное тело ответа, консольный вывод, ошибки, длительность API-операции
и код завершения. Метрики `usage` сохраняются, если провайдер их вернул.
Записи — обычный UTF-8 текст; содержимое сообщений экранируется как JSON-строка,
поэтому многострочные сообщения не смешиваются с границами записей.

Значение настроенного API-ключа заменяется на `[REDACTED]`, заголовок
Authorization не записывается. Сырые исключения не выводятся.
Запросы и ответы сохраняются: перед публикацией видео проверяйте их содержимое.
`.log`, `.env` и виртуальное окружение исключены из Git.

Если журнал создать не удалось, API не вызывается. При сбое записи после
отправки запроса выполнение останавливается; сохранить запись на недоступный
диск невозможно.

Коды завершения:

| Код | Значение |
|---|---|
| 0 | Получен полный текстовый ответ или показана помощь |
| 1 | Сбой сети/API, некорректный ответ, отказ, обрезание, ошибка журнала |
| 2 | Ошибка аргументов или настроек |
| 130 | Пользователь прервал запрос через Ctrl+C |

Ответ идёт в stdout, сообщения об ошибках — в stderr. Обрезанный ответ
фиксируется в журнале и не выдаётся за успешный результат.

## BDD и проверки

```bash
.venv/bin/python -m pytest -q
```

Сценарии на русском: `tests/features/cli.feature`. Сначала были написаны тесты,
затем проверено их падение на заглушке, затем добавлена реализация.
История проверок описана в `BDD.md`.

Автотесты используют `httpx.MockTransport`: ключ не требуется, платных запросов
нет. Они моделируют транспортные ошибки на границе HTTP-клиента; реальное
отключение интернета или падение Polza.ai не требуется. Настоящую доступность,
валидность ключа и ответ выбранной модели подтверждает отдельный ручной запуск.

## Демонстрация для сдачи

1. Покажите BDD-сценарий и запуск автотестов.
2. Покажите место формирования запроса в `src/day1/cli.py`, без `.env`.
3. Выполните реальный запрос и покажите ответ.
4. Откройте созданный `.log`: запрос, ответ и завершение.
5. Покажите один негативный пример: пустой запрос `day1 " "`.

Реальная демонстрация потребует настроенного ключа и положительного баланса.
Не выдавайте ответ из автотестов за ответ модели.

Документация: [API](https://polza.ai/docs/api-reference/chat/completions),
[настройка ключа](https://polza.ai/docs/gaidy/getting-started).
