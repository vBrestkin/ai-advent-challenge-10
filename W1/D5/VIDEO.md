# Сценарий видео D5 с реальным запуском

Ориентир — 5–7 минут плюс ожидание эксперимента, которое можно ускорить при монтаже.
Не открывайте .env и личные журналы. Каталог, README, тесты и submission/ безопасны
для показа после проверки. В журнале могут быть личные тексты диалогов.

## 1. Цель и условия — 30 секунд

«Сегодня сравниваю три уровня моделей одной линейки: Gemini 2.5 Flash-Lite,
Flash и Pro через Polza.ai. Для всех беру восемь задач из третьего дня и делаю
по три повтора. Измеряю правильность, время, токены и стоимость.
Запросы и формат одинаковые, каждый ответ начинается с чистой истории».

Откройте README.md и TASKS.md. Покажите, что эталоны доступны проверяющему коду,
а messages_for передаёт модели только условие.

## 2. BDD и тесты — 40 секунд

```bash
cd /Users/brestkin/ai-advent-challenge-10/W1/D5
.venv/bin/python -m pytest -v
```

Откройте tests/features/day5.feature и BDD.md.

«Сначала написаны сценарии поведения и падающие автотесты, затем реализация.
Тесты работают без реальной модели. Они проверяют одинаковые условия,
оценку ответов, бюджет, сохранение истории, сетевые ошибки и продолжение
после прерывания без повторного списания».

## 3. Выбор моделей — 40 секунд

```bash
.venv/bin/day5 catalog
```

Покажите тарифы, supported_parameters и json_schema_strict трёх моделей.

«Модель и маршрут закреплены. У Pro рассуждение обязательно, поэтому у всех
трёх оно включено с одинаковым запрошенным бюджетом 1024 токена.
Температура 0,7 и общий лимит 4096 тоже одинаковые.
Фактическое число токенов может различаться. Это сравнение одного профиля
на трёх моделях, а не максимальных возможностей каждой».

## 4. Короткая демонстрация диалога — необязательно

Это отдельные платные запросы, они не входят в таблицу и лимит эксперимента.
Для сдачи D5 достаточно реального запуска эксперимента ниже.

```bash
.venv/bin/day5 chat --model medium --session video-d5
```

Введите «Запомни: мой учебный проект называется Маяк», затем «Как называется
мой проект?». Покажите /history и завершите /exit. При повторной съёмке
используйте новое имя сессии или /new.

«В обычном диалоге история сохраняется и передаётся в следующем запросе.
В эксперименте прошлые решения не передаются, чтобы модели были в одинаковых условиях».

## 5. Настоящий эксперимент — 30 секунд и ожидание

```bash
.venv/bin/day5 experiment --repeats 3 --budget-rub 50
```

«Сейчас выполняются реальные платные запросы. Сначала три пилота проверяют
поддержку параметров и наличие метрик. Затем 72 решения: восемь задач,
три модели и три повтора. Порядок перемешан. Пилот входит в общий бюджет
50 рублей, но не входит в таблицу качества».

Покажите первые строки pilot и records, затем ускорьте ожидание.
Каждый новый запуск без --resume создаёт новый эксперимент и новые списания.
Завершённый запуск с --resume новых запросов не делает и не заменяет демонстрацию
реального запуска. При прерывании продолжайте с путём, выведенным инструментом:

```text
.venv/bin/day5 experiment --repeats 3 --budget-rub 50 --resume АБСОЛЮТНЫЙ_ПУТЬ_ПРОГОНА
```

## 6. Таблица — 60 секунд

Откройте report.md именно в папке нового прогона, которую команда вывела в конце.
Покажите сводку, результаты по задачам, сравнение цены и бюджет.
summary.csv и details.csv содержат те же проверяемые данные.

«Здесь правильность отделена от доступности API. Сетевая ошибка не означает,
что модель неправильно решила задачу. Время — медиана полученных ответов,
стоимость — данные API. Reasoning уже входит в выходные токены.
Если после разрыва связи цена неизвестна, она не считается нулём».

Если есть неизвестные списания:

«Поэтому полное отношение реальных расходов не вычисляется. Отдельно показано
отношение стоимости на одинаковых парах задача/повтор с известными ценами.
Оно относится только к этой части эксперимента».

## 7. Вывод — 30–40 секунд

Используйте значения нового прогона, а не числа предыдущего отчёта.

«Маленькая модель дала [число] верных ответов, средняя — [число], флагманская —
[число] из 24 попыток каждая. На [задачи из отчёта] маленькой модели хватило
во всех трёх повторах. Флагман [показал / не показал] прирост качества на этом
наборе, при этом его стоимость на сопоставимых запросах составила [число]
стоимостей маленькой модели. Я бы выбирал модель по сложности задачи и
проверял, окупается ли доплата. Восемь задач — учебный пример, а не общий
рейтинг моделей».
