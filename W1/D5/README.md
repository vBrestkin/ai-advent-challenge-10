# День 5 — сравнение трёх моделей

Одна CLI-утилита для диалога с сохранением истории и сравнения Gemini 2.5
Flash-Lite / Flash / Pro через Polza.ai. Восемь задач из D3, три повтора на
модель: 72 основных вызова плюс три пилотных. Общий бюджет по умолчанию 50 ₽.
Pro — флагманская модель выбранной линейки 2.5; сравнение не претендует
на рейтинг всех актуальных флагманов разных поколений.

## Установка

```bash
cd /Users/brestkin/ai-advent-challenge-10/W1/D5
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/day5 --help
```

В рабочей копии окружение уже подготовлено. Ключ читается из `.env` D1 → D2 →
D3 → D4 → D5 → переменные окружения; поздние значения перекрывают ранние,
включая пустые. Существующий ключ из D1 повторно вводить не нужно.
Эксперимент всегда использует три фиксированные модели; LLM_MODEL задаёт
только модель диалога по умолчанию.

## Каталог и диалог

```bash
.venv/bin/day5 catalog
.venv/bin/day5 chat --model small --session lite-demo
.venv/bin/day5 chat --model medium --session flash-demo
.venv/bin/day5 chat --model flagship --session pro-demo
```

`catalog` не требует ключа и не вызывает платную генерацию. Все три маршрута
проверяются до эксперимента. История разговора сохраняется в `history/`; имя
сессии продолжает существующий разговор. Команды `/history`, `/new`, `/exit`.
Выбранная модель должна совпадать с сохранённой. Текстовые ходы передаются
в следующем запросе; внутренний reasoning в историю не переносится.

Общий профиль D5: temperature=0.7, reasoning.enabled=true,
reasoning.max_tokens=1024, max_tokens=4096. У Pro thinking обязателен.
Профиль D3 min/max и лимиты D3 не переносятся автоматически. Бюджет 1024
совместим с диапазонами Gemini 2.5; фактическое число reasoning-токенов
может различаться и превышать запрошенный бюджет. Чат использует тот же
профиль без строгого формата; эксперимент задаёт JSON Schema.
Длинный ответ в чате может быть обрезан: незавершённый ход остаётся только
в журнале. Для длинных бесед или других настроек доступны инструменты D3/D4.

Чат тарифицируется отдельно от бюджета эксперимента. Каждый ход включает
весь сохранённый контекст, автоматического сокращения контекста нет.

## Реальный эксперимент

```bash
.venv/bin/day5 experiment --repeats 3 --budget-rub 50
```

Команда сначала проверяет каталог трёх моделей и выполняет по одному
пилотному запросу на T8. Пилот проверяет модель, завершённость, схему,
наличие метрик и положительный reasoning-счётчик, согласованность токенов.
Неверный математический ответ сам по себе не означает несовместимость API.
Если пилот не пройден, основной прогон не начинается, доказательства сохраняются.

Каждое решение использует одинаковые system/user сообщения без эталона,
одинаковую строгую схему `{"answer":"строка"}`, температуру и reasoning.
Каждая попытка начинает чистый контекст; прошлые ответы не подмешиваются.
В каждом повторе порядок 24 комбинаций перемешан с локальным seed=42.
Это seed порядка, а не генерации модели. Все три модели закреплены на
`google-ai-studio/flex`, fallback и автоматические повторы отключены.
Различаются модель и соответствующее ей ограничение цены маршрута.
Если шлюз не возвращает поле provider, фактический backend независимо
не подтверждён: закрепление маршрута проверяется по исходному запросу,
идентификатор модели — по ответу API. Пустое поле не заменяется запрошенным именем.

Пилот входит в бюджет, но исключён из основной таблицы. Перед каждым вызовом
резервируется оценка входа и максимальная стоимость выхода. Цена маршрута
ограничена снимком каталога +1%. Неизвестные списания сохраняют полный резерв,
а не становятся нулями. Это локальный ограничитель, не гарантия банковского биллинга.
API-, форматные, математические ошибки, обрезание и подмена модели считаются
отдельно. HTTP 400/401/402/403/404/413/422 останавливают дальнейшие вызовы.

Папка прогона выводится в конце команды:

```text
/Users/brestkin/ai-advent-challenge-10/W1/D5/results/YYYY-MM-DD_HH-MM-SS_id/
```

Продолжение незавершённого прогона с теми же настройками:

```bash
.venv/bin/day5 experiment --repeats 3 --budget-rub 50 \
  --resume /абсолютный/путь/к/папке/прогона
```

Уже учтённые попытки, включая сетевые ошибки и прерывания, не повторяются.
Перед POST сохраняется маркер неизвестного исхода с резервом. Это предотвращает
повторный вызов после аварийного завершения; возможна консервативная потеря
попытки, если процесс завершился после записи маркера, но до отправки запроса.
Проваленный пилот при resume не повторяется; основной прогон остаётся заблокирован.
Новый запуск без --resume создаёт новую папку и новые платные запросы.
Одновременный запуск двух процессов с одной папкой прогона или сессией
не поддерживается. Для другого эксперимента создавайте отдельный запуск.

Таймаут подключения 10 с, чтения 180 с. Они меняются через --connect-timeout
и --read-timeout; таймаут чтения не равен общему времени выполнения процесса.

## Результаты и сдача

В папке прогона сохраняются results.json, catalog.json, raw/*.json,
summary.csv (три модели), details.csv (72 попытки), tasks.csv (задача × модель),
comparisons.csv (цена / точность / время относительно маленькой) и report.md.
При остановке отчёт содержит уже выполненную часть.

Медианное время считается по завершённым ответам выбранной модели. Суммарное
время всех HTTP-попыток сохраняется отдельно. Thinking входит в completion и
total, поэтому не прибавляется повторно. Стоимость берётся из usage.cost_rub.
Отсутствующие метрики помечаются unknown_*. Стоимость верного решения и
отношение реальных расходов не вычисляются при неизвестных списаниях.
Дополнительно показывается отношение стоимости на сопоставимых парах
задача/повтор с полученными ответами и известной ценой у обеих моделей.
Эта оценка относится только к указанному числу пар, а не ко всему прогону.

Качество показано как верные / все попытки и верные / полученные ответы.
Пригодные ответы также сравниваются попарно на одинаковых задаче и повторе.
Три повтора восьми задач не дают универсального рейтинга моделей.
Условия и эталоны: TASKS.md; строгая оценка дробей, множеств и чисел — tasks.py.

Проверенные материалы сдачи находятся в `submission/`, сценарий видео — VIDEO.md.
Локальные `.env`, `.venv`, логи, личная history/ и рабочие results/ исключены
из Git. Код, тесты и проверенные материалы submission/ предназначены для репозитория.

## Логи и тесты

Каждый запуск, включая --help и ошибки аргументов, пишет UTF-8
`logs/YYYY-MM-DD_HH-MM-SS_<id>.log`. В журнале ввод, вывод, запросы,
ответы, метрики, ошибки и завершение. Ключ маскируется, Authorization
не сохраняется. Истории и JSON-чекпоинты создаются с правами 600.
Если журнал недоступен до вызова, работа прекращается. При физическом отказе
диска после запроса его ответ может не сохраниться; маркер попытки остаётся.

```bash
.venv/bin/python -m pytest -v
```

Тесты офлайн, баланс API не расходуют. BDD-сценарии — tests/features/day5.feature,
цикл red → green — BDD.md. Коды завершения: 0 — все запланированные попытки
учтены (это не обещание правильности); 1 — ошибка или остановка; 2 — настройки;
130 — Ctrl+C.

Источники: [каталог](https://polza.ai/docs/api-reference/models/list),
[reasoning](https://polza.ai/docs/osobennosti/reasoning-tokens),
[бюджеты Gemini](https://ai.google.dev/gemini-api/docs/generate-content/thinking?hl=en).
