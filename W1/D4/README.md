# День 4 — температура и разнообразие

CLI поддерживает диалог с историей и температурой, а также эксперимент:
два запроса × три температуры × пять повторов = 30 API-вызовов.
Готовые таблицы, выводы и исходные ответы находятся в `submission/`.

## Запуск

В текущей папке виртуальное окружение и команда уже установлены:

```bash
cd /Users/brestkin/ai-advent-challenge-10/W1/D4
.venv/bin/day4 --help
.venv/bin/day4 chat --session demo --temperature 0
```

Для установки с нуля (Python 3.9+):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e '.[test]'
```

Ключ повторно вводить не нужно. Настройки загружаются в порядке `.env` D1 →
D2 → D3 → D4 → окружение. Поздние значения перекрывают ранние, включая пустые.
Для отдельной установки заполните локальный `.env` по примеру, не добавляя ключ в Git.

## Диалог и сохранение настроек

Температуру можно задать в диапазоне 0–2:

```bash
.venv/bin/day4 chat --session creative --temperature 1.2
.venv/bin/day4 chat --session creative
```

Второй запуск восстанавливает историю и температуру, включая ноль. Явная
попытка изменить настройки существующего разговора отклоняется — создайте
другое имя сессии. `/history` показывает сообщения, `/new` создаёт отдельный
разговор с теми же настройками, `/exit` завершает работу. Без --session каждый
запуск создаёт новый разговор. EOF — обычное завершение, Ctrl+C — код 130.

Настройки сохраняются вместе с моделью, маршрутом, reasoning и сообщениями
user/assistant. Незавершённый ход не попадает в успешную историю, а остаётся
в журнале. Запись атомарная, повреждённый файл не перезаписывается.
Одновременная работа нескольких процессов с одной историей не поддерживается.
Контекст не обрезается автоматически: при переполнении начните новый разговор.

Сохранены режимы --reasoning off/min/max. Для эксперимента всегда используется
min: включённое thinking с бюджетом 512. Его нельзя называть отключённым.
В диалоге общий лимит по умолчанию 32768 и --max-tokens принимает 24577–65535,
чтобы поддерживать максимальный thinking-профиль. В эксперименте лимит отдельный — 4096.

Таймаут подключения — 10 секунд, чтения — 180, параметры --connect-timeout
и --read-timeout. Таймаут чтения не является общим дедлайном процесса.

## Реальный эксперимент

```bash
.venv/bin/day4 catalog
.venv/bin/day4 experiment --repeats 5 --budget-rub 5
```

`catalog` проверяет публичные метаданные без генерации. `experiment` отправляет
30 платных запросов и печатает папку результатов. Профиль модели:
google/gemini-2.5-flash-lite, маршрут google-ai-studio/flex.

Проверяются поддержка temperature/reasoning/max_tokens, лимит и рублёвые цены.
Диапазон temperature в документации Polza.ai — 0–2; выбранные 0, 0.7 и 1.2
в него входят. Каталог — предварительное подтверждение, а не независимая
аттестация реализации backend. Фактические ответы и ошибки сохраняются.

Фиксированные условия:

- **Логика:** количество двоичных строк длины 12 с пятью несоседними единицами;
  правильный ответ 56. Модель получает условие, но не эталон.
- **Генерация:** пять разных коротких названий приложения для изучения Python.
- JSON описан только в промпте. response_format/JSON mode/строгая схема API не передаются.
- Reasoning-бюджет 512, max_tokens=4096, модель и маршрут неизменны. Меняется только температура.
- Каждый прогон имеет пустую историю с одинаковыми system/user для своего типа задачи.
- Внутри каждого повтора порядок шести комбинаций перемешан с seed=42 на стороне
  программы. Seed модели, stop, top_p и другие параметры сэмплинга не передаются.
- Повторы независимы по контексту. Отсутствие скрытого кэша и стабильность
  внутреннего backend не гарантируются.

Точные промпты, проверки и параметры хранятся в `results.json`.

### Что измеряется

1. Получен ли полный ответ выбранной модели; API-ошибка и обрезание учитываются отдельно.
2. Разбирается ли исходный текст как JSON; Markdown и повреждённые фрагменты не исправляются.
3. Соответствует ли JSON локальной схеме полей и типов. Схема используется только проверяющим кодом.
4. Правилен ли числовой ответ. При неверном формате правильность неизвестна, а не равна false.
5. Для названий — ровно пять непустых различных строк после нормализации. Это проверка требований, не художественного качества.
6. Число уникальных исходных текстов, нормализованных ответов и названий, среднее сходство наборов по Жаккару.
7. Время, входные/выходные/общие/reasoning-токены и стоимость из usage.

Нормализация названий: Unicode NFKC, casefold, удаление крайних и схлопывание
внутренних пробелов. Пунктуация не удаляется. Перестановка тех же названий
не считается новым набором. Для числа 56 и 56.0 нормализованные ответы совпадают.

Пул названий и Жаккар считаются по пригодным спискам. Жаккар — пересечение /
объединение двух наборов: 1 означает совпадение, 0 — отсутствие общих названий.
При менее двух пригодных ответах среднее не вычисляется. Число пригодных
списков показывается явно; пулы при разном числе списков нельзя сравнивать напрямую.

При temperature=0 сравниваются и исходные строки, и нормализованные данные.
Даже совпадение всех пяти наблюдений не доказывает гарантированной повторяемости
для любого запроса. Новая запись видео создаст новую выборку, цифры могут отличаться.

### Файлы и продолжение

В `results/<дата_id>/` сохраняются report.md, summary.csv (6 строк), details.csv
(30 строк при полном прогоне), results.json, raw/*.json и каталог перед запросами.
CSV — UTF-8 с BOM. Известные расходы суммируются отдельно от неизвестных;
reasoning уже входит в total, повторно к нему не прибавляется.

```bash
.venv/bin/day4 experiment --repeats 5 --budget-rub 5 --resume "/папка/этого/прогона"
```

При продолжении настройки и бюджет должны совпадать. Выполненные попытки,
включая сетевые ошибки и прерванный активный запрос, не повторяются. Активный
запрос мог быть обработан до разрыва/прерывания, поэтому его цена остаётся
неизвестной и покрывается резервом. Неполный набор помечается interrupted,
budget_stopped или request_rejected, без выдуманных ответов.

Перед вызовом резервируется верхняя оценка выхода и входа с запасом. При
неизвестном списании резерв сохраняется. Запрос не отправляется при нехватке
бюджета с учётом резервов; стоимость маршрута ограничена снимком каталога +1%.
Это локальная защита, а не банковская гарантия биллинга. Авторизационные и
систематические ошибки параметров останавливают прогон до дальнейших вызовов.
Автоматические повторы и fallback отключены.

## Логи и BDD

Каждый запуск пишет UTF-8 журнал `logs/YYYY-MM-DD_HH-MM-SS_<id>.log`: ввод,
команды, вывод, запросы, ответы, метрики, ошибки и завершение. Известный ключ
маскируется, Authorization не сохраняется. Истории и журналы создаются с правами 600.
Если журнал недоступен, работа останавливается; после отказа диска уже
отправленный запрос может оказаться физически невозможно записать.

`.env`, .log, виртуальное окружение, личные history/ и результаты рабочих
запусков исключены из Git. Проверенные учебные материалы для сдачи — в submission/.

```bash
.venv/bin/python -m pytest -v
```

Тесты офлайн, API-баланс не расходуют. Сценарии и цикл разработки — в tests/
и BDD.md. Коды: 0 — команда завершена; 1 — ошибка/неполный эксперимент;
2 — неверные настройки; 130 — Ctrl+C. Код 0 эксперимента означает, что
попытки учтены, а не что все ответы правильны.
