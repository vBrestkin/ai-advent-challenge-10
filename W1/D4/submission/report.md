## temperature = 0: одинаков ли ответ?

Задача с одним ответом: из 4 полученных ответов все тексты одинаковы. Это наблюдение, а не гарантия для следующих запросов. После нормализации: 1 уникальных наборов данных среди 4 структурно корректных ответов.
Генерация названий: из 4 полученных ответов все тексты одинаковы. Это наблюдение, а не гарантия для следующих запросов. После нормализации: 1 уникальных наборов данных среди 4 структурно корректных ответов.

## Выводы

- T=0, логика: верных 4, неверных 0, форматных сбоев 0, ошибок API 1 из 5 попыток. Изменение единственного правильного числа не является полезным разнообразием.
- T=0.7, логика: верных 1, неверных 4, форматных сбоев 0, ошибок API 0 из 5 попыток. Изменение единственного правильного числа не является полезным разнообразием.
- T=1.2, логика: верных 0, неверных 4, форматных сбоев 0, ошибок API 1 из 5 попыток. Изменение единственного правильного числа не является полезным разнообразием.
- T=0, названия: 5 различных названий в 4 пригодных списках, 1 различных наборов среди 4 структурно корректных ответов. Доля уникальных: 0.25.
- T=0.7, названия: 20 различных названий в 5 пригодных списках, 5 различных наборов среди 5 структурно корректных ответов. Доля уникальных: 0.8.
- T=1.2, названия: 19 различных названий в 5 пригодных списках, 5 различных наборов среди 5 структурно корректных ответов. Доля уникальных: 0.76.

Правильность математического ответа среди структурно проверяемых ответов: T=0: 4/4; T=0.7: 1/5; T=1.2: 0/4. API-сбои и ошибки формата в эти знаменатели не включены.

Повышение температуры с 0.7 до 1.2 не увеличило пул уникальных названий: 20 → 19 при одинаковом числе пригодных ответов (5). Рост температуры не обязан давать монотонный рост разнообразия.

Практическое применение: 0 — отправная точка для задач с фиксированным ответом и повторяемой формой; правильность всё равно нужно проверять. 0.7 — кандидат для обычной генерации идей, 1.2 — кандидат для поиска более необычных вариантов с последующим отбором. Это направления использования, а не гарантия качества или монотонного роста разнообразия. Для автоматической обработки JSON одной инструкции может быть недостаточно — формат проверяется кодом.

## Условия сравнения

- Один и тот же пользовательский запрос и системная инструкция для всех температур каждого типа задачи.
- Пять повторов по умолчанию. Каждая попытка — пустая история с system/user, без переноса прошлых ответов.
- Reasoning включён с одним бюджетом 512, max_tokens=4096. Меняется только temperature.
- Нативная JSON Schema/JSON mode, stop и seed не передаются. Ожидаемый JSON задан только промптом.
- Нормализация названий: Unicode NFKC, casefold, удаление крайних и схлопывание внутренних пробелов. Пунктуация не удаляется.
- Уникальные тексты — точное совпадение исходных ответов. Уникальные данные — JSON после нормализации; порядок названий не учитывается.
- Разнообразие названий считается только по пригодным спискам из пяти непустых различных названий.
- API-, незавершённые и несовпадающие по модели ответы исключаются из оценки разнообразия. Ошибки JSON сохраняются отдельно.
- Шлюз выбирает backend внутри запрошенного маршрута; параметры переданы явно, внутренняя реализация не аттестована независимо.
- Порядок шести комбинаций перемешан внутри каждого повтора с seed=42 только на стороне программы; это не seed модели.
- Разнообразие может быть немонотонным; пять наблюдений на одном запросе не дают универсального вывода о всех задачах.
- Сырые ответы не исправляются: Markdown не вырезается. Thinking уже входит в total и не прибавляется второй раз.
- Полные данные: results.json, raw/*.json, catalog*.json. Схема проверки локальная и не ограничивает генерацию на сервере.
