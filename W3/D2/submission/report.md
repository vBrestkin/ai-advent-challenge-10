# День 12 · как профиль меняет ответы ассистента

Два профиля по-разному ответили на один вопрос. После просьбы в чате ассистент сменил настройки и применил их к следующему ответу. В отдельном разговоре с кратким профилем все 10 ответов уложились в критерии формата.

## 1. Один вопрос, два профиля

Оба новых разговора получили вопрос «Как посчитать, сколько раз каждое слово встречается в списке?». У них не было предыдущих сообщений. Использовалась одна модель Qwen3 14B через Polza.ai с запрошенным маршрутом `deepinfra/fp8`. Менялся профиль.

| Профиль | Что проверяли | Что получили | Соблюдено |
|---|---|---|---:|
| Кратко и без кода | До 45 слов, без отдельного блока кода | 21 слово, без блока кода | 2/2 |
| Подробно и с кодом | От 100 слов пояснения, отдельный блок с кодом | 122 слова, блок Python | 2/2 |

**Краткий ответ целиком.** «Это можно сделать, создав словарь, где ключами будут слова, а значениями — их количество. Пройдитесь по списку, увеличивая счётчик для каждого слова».

**Подробный ответ** разбирает алгоритм по шагам, показывает функцию `count_words` и приводит результат для списка фруктов. Полный ответ есть в CSV и сохранённом диалоге. Короткий ответ даёт сам способ, а подробный добавляет рабочий пример.

## 2. Как профиль обновился из диалога

1. Третий разговор начали с настроек «подробно, с кодом».
2. Отправили отдельную реплику «Теперь отвечай кратко и без кода». Ассистент подтвердил: «Хорошо, буду отвечать кратко и без кода». Приложение сохранило новые настройки.
3. Задали тот же вопрос о частоте слов. Ассистент ответил: «Создайте словарь, пройдитесь по списку слов, увеличивайте счётчик для каждого слова». Это **11 слов без блока кода**.
4. Заново открыли базу и проверили профили всех четырёх разговоров. Настройки восстановились. Разговор №2 сохранил свой подробный профиль.

## 3. Десять вопросов подряд

Все вопросы отправлялись в один разговор с профилем «кратко, без кода». Каждый успешный ход записывался в историю. Настройка добавлялась к запросу на каждом ходе, а недавние реплики брались из окна истории.

| № | Тема | Слов | Блок кода | Критерии соблюдены |
|---:|---|---:|---|---|
| 1 | Словарь Python | 20 | Нет | Да |
| 2 | Список и множество | 13 | Нет | Да |
| 3 | Удаление дубликатов | 14 | Нет | Да |
| 4 | Сортировка по ключу | 20 | Нет | Да |
| 5 | Виды копирования | 14 | Нет | Да |
| 6 | Валидация входных данных | 18 | Нет | Да |
| 7 | Исключения | 17 | Нет | Да |
| 8 | Подмена API в тестах | 13 | Нет | Да |
| 9 | Журналирование | 16 | Нет | Да |
| 10 | Проверка после перезапуска | 15 | Нет | Да |

**Первого нарушения в этой серии не было.** Получили 10/10 по двум критериям. Слова считались вне отдельных блоков Markdown. Такое измерение проверяет длину и наличие блока кода. Содержательность и корректность ответа требуют отдельной проверки.

## Что показал первый прогон

Краткий ответ на общий вопрос и ответ после смены профиля формально прошли проверку. По смыслу они были неудачными: модель ссылалась на недоступность инструмента и не объясняла алгоритм. Кроме того, в серии первого прогона она предложила использовать множество для сохранения порядка при удалении дубликатов. Этот совет не гарантирует порядок.

В персонализированном чате я заменил системную роль помощника по заказам на роль обычного ассистента с отдельными правилами применения инструментов. Затем повторил весь сценарий. Во втором прогоне оба профиля объяснили алгоритм подсчёта. Результаты первого прогона сохранены в `attempt_01/`. Второй прогон показывает результат для этого набора вопросов, а устойчивость за пределами десяти ходов не измерялась.

| Прогон | Запросов | Токенов API | Цена |
|---|---:|---:|---:|
| Первый | 14 | 15 777 | 0,23326133 ₽ |
| Второй | 14 | 16 498 | 0,24293842 ₽ |
| Всего | 28 | 32 275 | **0,47619975 ₽** |

Общий лимит составлял 20 ₽. Неизвестных списаний не было. В `details.csv` лежат точные ответы второго прогона, в `experiment.json` и `trace.json` — сохранённые профили, метрики и запросы.
